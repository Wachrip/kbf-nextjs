# КБФ — публичный сайт (Next.js)

Сайт Кыргызской баскетбольной федерации. Только читает Firestore проекта `kbf-site`; данные
пишет админка (Flutter Web, репозиторий `kbf`). Вёрстка — перенос утверждённой дизайн-системы
«КБФ — дизайн-система» и макетов 17 страниц один в один по классам `k-*`.

Стек: Next.js 16 (App Router, `cacheComponents`), React 19, TypeScript strict, Tailwind 4, pnpm.

## Запуск

```bash
pnpm i
cp .env.example .env.local    # KBF_DATA оставлен пустым — режим выбирается явно
pnpm dev:mock                 # фикстуры, без сети и без базы (= KBF_DATA=mock next dev)
KBF_DATA=firestore pnpm dev   # боевая база kbf-site через REST
pnpm typecheck && pnpm lint
KBF_DATA=mock pnpm build && KBF_DATA=mock pnpm start   # локальная прод-сборка на фикстурах
```

`next/font` скачивает Manrope и Oswald при сборке — нужна сеть один раз; в рантайме внешних
запросов к шрифтам нет.

## Скорость: dev и прод

`pnpm dev` медленный по устройству: каждый маршрут компилируется при первом заходе (секунды),
`"use cache"` и пререндер не работают как в проде, данные читаются из Firestore заново. При
медленном интернете это складывается. Скорость оценивать только на прод-сборке:

```bash
KBF_DATA=firestore pnpm build && KBF_DATA=firestore pnpm start
```

В проде детальные страницы пререндерены (`generateStaticParams`), списки отдают статическую
оболочку, данные — из кэша на 5 минут; Firestore на запрос посетителя не читается, пока кэш
свежий.

Отклик на клик:
- **Полоска перехода** `NavProgress` (островок в layout, вне `.k-page`): стартует на клик по
  внутренней ссылке, submit GET-формы, back/forward; показывается, если переход дольше
  150 мс; гаснет при смене адреса или через 15 с. `prefers-reduced-motion` — без анимации.
- **Нажатый чип и номер страницы** приглушаются (`LinkPending` — `useLinkStatus` в потомке
  серверного `Link`, `aria-busy`).
- **Скелеты** — только у `/players` и `/games` (Suspense-оболочка, `ListSkeleton`).
  `loading.tsx` для страниц с `instant = false` (`/news`, `/news/[slug]`, `/games/[id]`,
  `/players/[slug]`, `/tournaments/[slug]`, команда) намеренно нет: `loading.tsx` — это
  Suspense над страницей, ответ уходит со статусом 200 до `notFound()`/`permanentRedirect()`,
  и настоящие 404/308 превратились бы в «мягкие». Эти страницы пререндерены, в проде
  переход на них — из кэша; ожидание видно по полоске.
- **Недоступный Firestore.** Списки показывают пустое состояние (лог `[data]`), поиск записи
  по slug/id — ошибку (`error.tsx`, 500), а не 404. Устаревшая версия страницы отдаётся,
  только пока жива запись кэша (до `expire` и до перезапуска инстанса): с `minInstances: 0`
  после простоя кэша нет — детальные страницы отвечают 500. Если Firestore недоступен при
  сборке, падает вся сборка, на сайте остаётся предыдущий выкат.
- **«Сейчас» (`getNow`)** кэшируется отдельно, `expire` 5 минут (чтобы после простоя табло
  дня не показало вчерашнее). Цена: после 5 минут без посетителей первый запрос рендерит
  страницу блокирующе — ждёт пересчёта `getNow` и всего, что от него зависит (табло,
  ближайшие матчи, возраст), вместо мгновенной отдачи из кэша; данные Firestore при этом из
  своего кэша (expire 1 час), так что ожидание — это рендер, а не чтение базы. Короче 5
  минут `expire` ставить нельзя: кэш станет «коротким» и выпадет из пререндера (dynamic hole,
  `cacheLife.md`).
- **PDF протокола** встраивается (`iframe`, десктоп) только из бакета Storage проекта
  (`isStorageUrl`), иначе — только кнопка «Открыть». «Скачать» нет: атрибут `download` у
  чужого origin браузер игнорирует, а `response-content-disposition` у download URL Firebase
  не гарантирован. `sandbox` у iframe не стоит
  намеренно: в sandbox-фрейме Chrome не показывает PDF (встроенный просмотрщик — плагин, а
  плагины в sandbox запрещены); риск закрыт ограничением хоста.
- **REST-клиент**: таймаут 5 с на попытку (вместе с телом ответа), один повтор через 300 мс
  при сбое сети, таймауте, 429 и 5xx; худший случай ≈ 10 с, затем пустое состояние.

## Переменные окружения

| Переменная | Значение | Где |
| --- | --- | --- |
| `KBF_DATA` | Обязательна. `firestore` — боевая база через REST; `mock` — фикстуры по сиду админки, только явно (`pnpm dev:mock`). Пусто или другое значение — ошибка в лог, рендер и сборка падают (фикстуры не попадут на сайт молча) | сервер |
| `NEXT_PUBLIC_FIREBASE_PROJECT_ID` | `kbf-site` (по умолчанию) | сервер, `next.config.ts` (бакет фото) |
| `NEXT_PUBLIC_VIEW_TRANSITIONS` | `on` (по умолчанию) / `off` — переходы между страницами (см. «Книга дизайна») | клиент и сервер, на сборке |
| `NEXT_PUBLIC_SITE_URL` | адрес сайта без `/` в конце: canonical, Open Graph, sitemap, JSON-LD. Не задан в production — `robots.txt` закрывает индексацию | сервер |

Переезд на домен — правка одной строки `NEXT_PUBLIC_SITE_URL` в `apphosting.yaml`.

## Архитектура

```
src/
  app/            маршруты: page.tsx — тонкие, данные из data/repo, разметка из components/
  components/
    layout/       шапка, подвал, логотип (серверные; подвал читает settings/about)
    ui/           серверные компоненты дизайн-системы (k-*): карточки, матчи, таблица, новости
    islands/      *.client.tsx — единственные клиентские островки
    seo/          JSON-LD
  data/           только сервер (import "server-only"): REST-клиент, нормализация, источники, кэш
  lib/            чистые функции и типы — общие для сервера и островков
  styles/         tokens.css (токены), kbf.css (перенос bundle.css), kbf-extra.css (продакшен-дополнения и правки)
```

- **Данные.** `data/firestoreRest.ts` — REST-клиент Firestore без ключа и SDK (из piromag-market,
  расширен: `orderBy`, `offset`, диапазоны, проекция `select`/`mask`, `count` через
  `runAggregationQuery`, таймаут 5 с на попытку и один повтор). `data/normalize.ts` повторяет мапперы админки (значения по
  умолчанию, `enum.name`). `data/getSource.ts` переключает `firestore`/`mock` по `KBF_DATA`.
- **Кэш.** `data/repo.ts`: каждая функция данных — `"use cache"` + `cacheLife({ stale: 300,
  revalidate: 300, expire: 3600 })` + `cacheTag("kbf:<коллекция>")`. Ошибка Firestore не роняет
  страницу: исключение не кэшируется, наружу — лог `[data] …` и пустое значение (пустые состояния
  на страницах). «Сейчас» (`getNow()`) тоже из кэша — `Date.now()` вне кэша ломает пререндер.
  Позже: вебхук из админки → `revalidateTag("kbf:posts")` и т. п.
- **Чтения.** Справочники (`teams`, `coaches`, `gyms`, `tournaments`, `games`, `players`) малы и
  читаются целиком с проекцией (`mask.fieldPaths`): без служебных полей, у `players` и
  `coaches` — без биографии. Новости — постранично (`offset/limit`, `select`; тело читается
  только чтобы посчитать время чтения и в кэш не попадает); число страниц и проверка `?tag`
  — по индексу новостей (`slug, tags, publishedAt`, одна кэшированная выборка). Статья,
  игрок и тренер — по `slug` целиком. `countQuery` (`runAggregationQuery`) в REST-клиенте
  оставлен, лентой сейчас не используется. Каждая выборка пишет в лог
  `[firestore] build|runtime …: N док.`.
- **Сезон и составы.** Текущий сезон — `settings/season.current` (`getCurrentSeason()`; нет
  документа — по дате: с августа сезон текущего года). Формат `YYYY-YY` (`lib/season.ts`;
  старые `2026/27` у турниров приводятся при чтении). Составы — коллекция `memberships`
  (`getMemberships({ season })` — все записи сезона для списка игроков, `{ teamId }` — команда
  по всем сезонам, `getPlayerMemberships(playerId)` — карьера). Логика составов — чистые
  функции `lib/membership.ts` (активная запись, состав сезона и «Покинули команду», главная
  запись игрока, период «с … / до …»). Пока записей нет совсем (база до миграции) — составы
  по `player.teamIds`, как в v1. Теги кэша: `kbf:memberships`, `kbf:settings` (season и about).
- **Маршруты.** Детальные страницы — `generateStaticParams` (все записи на сборке) +
  `instant = false` (slug читается до Suspense → настоящий 404). Пустой список параметров →
  заглушка `__placeholder__` (cacheComponents не принимает пустой массив). Списки с фильтрами
  (`/players?division`, `/games?division`) читают `searchParams`
  внутри `<Suspense>` — статическая оболочка + данные из кэша; так же `?region`, `?type`,
  `?season` (308 на мусор — `proxy.ts`, см. «Маршруты»). Только `/news` читает параметры до
  Suspense (настоящий 404). `dynamicParams` с
  `cacheComponents` несовместим — неизвестный дивизион даёт `notFound()`.
- **Островки** (`"use client"` только здесь): `HeaderNav` (активный пункт, бургер-меню
  порталом), `CopyLink`, `PlayersBrowser` (поиск/команда/амплуа по загруженному списку),
  `GymGallery` (свайп, стрелки, полоса миниатюр,
  автопрокрутка без `prefers-reduced-motion`), `NewsGallery` (мозаика `.k-gal` + полноэкранный
  просмотр). `PlayersBrowser` фильтрует ещё и по году рождения.
  ESLint запрещает импорт `@/data/*`, `next/cache`, `server-only` в `islands/`, `ui/`, `lib/`.
- **Стили.** Токены `tokens.json` → CSS-переменные (`styles/tokens.css`) и `@theme` Tailwind
  (`app/globals.css`, утилиты `bg-navy`, `text-ink`, `rounded-md`…). Классы `k-*` — в
  `@layer components`, адаптив — контейнерные запросы от корня `.k-page` (как в книге).
  Плейсхолдеров `k-ph*` нет: `next/image` или инициалы/первая буква.
- **Изображения.** Только `next/image` с `sizes`; оптимизатор принимает фото бакета
  `kbf-site.firebasestorage.app` (`remotePatterns` + `lib/images.ts`) и `/images/*`.
- **Cloudflare.** В рантайме только `fetch` и стандартный JS — без Node-специфики. Подробно —
  раздел «Переезд на Cloudflare».

## Маршруты

`/news` сейчас полностью динамическая: `instant = false` и чтение `searchParams` до Suspense
(нужно для настоящих 404 и 308 при мусорных `?page`/`?tag`), поэтому статической оболочки нет
и страница рендерится на каждый запрос. Данные ленты при этом из кэша (`"use cache"`, 5 минут),
Firestore на каждый запрос не дёргается. Канонизация `?page=1`, `?page=abc`, неизвестного
`?tag` — 308 (`permanentRedirect`).

Фильтры составов и регионов устроены иначе — страницы остаются статическими:
`/teams/[division]?region`, `/gyms?type&region`, `/tournaments?region` и `?season` команды
пререндерятся без фильтра (это и есть оболочка в CDN), а параметр читается внутри
`<Suspense>`. Канонизация — в `src/proxy.ts` по статическим спискам: неизвестный регион
(`REGION_IDS`, у турниров ещё `republic`), тип площадки, формат сезона, пустое или
повторённое значение — 308 на адрес без параметра. Что можно проверить только по данным
(регион, которого нет у команд дивизиона; фильтр скрыт при одном регионе; сезон, которого нет
у команды, или текущий), страница обрабатывает без редиректа: список без фильтра, у команды —
текущий состав. Метаданные этих страниц статические (не читают `searchParams`): заголовок не
зависит от фильтра, canonical — всегда чистый адрес, в том числе у отфильтрованных списков и
архивного сезона.

**Почему канонизация в `proxy.ts`, а не в `redirects()`.** `redirects()` в next.config не
умеет убрать параметр: Next передаёт исходный query в адрес назначения целиком
(`prepare-destination.js`, «Query merge order»: исходный query → параметры пути → query
назначения), поэтому редирект `/gyms?type=xxx` → `/gyms` вернулся бы на `/gyms?type=xxx` и
зациклился. Переопределить ключ можно, удалить — нет. Поэтому 308 остаётся в `proxy.ts`
(Next 16, работает и при клиентских переходах); на Cloudflare — см. «Переезд на Cloudflare».

**Цена proxy.** По опыту piromag-market CDN App Hosting может не кэшировать ответы маршрутов,
на которых срабатывает proxy (`/teams/:division`, `/teams/:division/:slug`, `/gyms`,
`/tournaments`). Проверить после выката: заголовки `cache-control`/`x-cache` у этих страниц.
Если CDN их не кэширует, сузить `matcher` (только адреса с query) или перенести 308 в правила
CDN.

**Отступление от брифа («невалидное значение → 308»).** 308 дают только значения, неверные
по статическим спискам (proxy). Корректный по формату, но отсутствующий у команды `?season`
и регион из `Region`, которого нет в данных, дают 200 со страницей без фильтра (у команды —
текущий состав) и чистым canonical: проверка требует данных, а внутри `<Suspense>` статус уже
не поменять. Делать её в proxy — чтение Firestore на каждый запрос с фильтром; дубль контента
закрывает canonical.

`/news` по этой схеме не переведена: 404 для страницы вне диапазона и проверка `?tag`
требуют данных (индекс новостей), в proxy их нет, а внутри `<Suspense>` настоящий 404 уже не
отдать (статус 200 ушёл с оболочкой).

## Деплой: Firebase App Hosting

Один раз: Firebase Console → App Hosting → создать бэкенд в проекте `kbf-site` с ID
**`kbf-web`**. Регион: **`asia-southeast1`** (там же Firestore), если он есть в списке;
App Hosting доступен не во всех регионах (по блогу Firebase на октябрь 2024 — `us-central1`,
`asia-east1`, `europe-west4`), иначе — **`asia-east1`** (ближайший). После создания взять
фактический адрес бэкенда из консоли и поправить `NEXT_PUBLIC_SITE_URL` в
`apphosting.yaml` (в шаблоне адреса есть регион). `apphosting.yaml` задаёт
`KBF_DATA=firestore`, проект, ресурсы, `SITE_NOINDEX=1` (демо) и `NEXT_PUBLIC_SITE_URL`
(шаблон адреса App Hosting — другой ID/регион или свой домен — поправить). Сервисный аккаунт и
секреты не нужны: сайт читает как гость.

**Путь 1 — локально, без GitHub.** `firebase.json` (бэкенд `kbf-web`, корень `.`, в архив не
идут `node_modules`, `.git`, `.next`, `scripts`, `.env*.local`, `firebase-debug*.log`) и `.firebaserc` (проект `kbf-site`) уже в
репозитории:

```bash
npm i -g firebase-tools        # нужна версия с App Hosting из локального источника
firebase login
firebase deploy --only apphosting          # или --only apphosting:kbf-web
```

Сборка идёт в облаке (Cloud Build) из загруженного архива исходников, `apphosting.yaml`
применяется так же.

**Путь 2 — через GitHub.** В консоли у бэкенда подключить репозиторий `client-kbf-nextjs`,
ветка `main`, корневая папка `/`, автоматический выкат включён: каждый push в `main` —
новая сборка. git и push — вручную.

**Сверить** (firebase-tools в node_modules нет, синтаксис взят из документации): поддержку
`firebase deploy --only apphosting` в установленной версии и поле `ignore` в
`firebase.json` → `apphosting` (`firebase --version`, `firebase deploy --help`). Если бэкенд
уже подключён к GitHub, локальный deploy может конфликтовать с автовыкатом — выбрать один путь.

## Перед выдачей ссылки на демо

1. Закрыть правила: `kbf/firestore.rules` ← `kbf/firestore.rules.new`, затем
   `firebase deploy --only firestore:rules,storage` (из репозитория `kbf`).
2. Проверить, что в `apphosting.yaml` `SITE_NOINDEX=1` и `NEXT_PUBLIC_SITE_URL` — фактический
   адрес бэкенда.
3. Прогнать `scripts/smoke.sh` против прод-сборки.

## Перед публичным запуском

- Снять `SITE_NOINDEX` в `apphosting.yaml` (сейчас `1`: robots.txt `disallow: /`, meta
  robots `noindex,nofollow`, `X-Robots-Tag`).
- Домен: привязать к бэкенду App Hosting, `NEXT_PUBLIC_SITE_URL` = домен (canonical, sitemap,
  Open Graph, JSON-LD), пересобрать.
- Правила Firestore (`firestore.rules.draft` → `kbf/firestore.rules`) и Storage (чтение
  фото — публично, запись — только админка), индексы (`firestore.indexes.json`).
- Lighthouse на прод-сборке (мобилка, медленная сеть): LCP, CLS, доступность.
- Реальные данные вместо сида: составы, цвета команд, фото, протоколы.

## Переезд на Cloudflare (OpenNext)

- **Кэш «use cache».** На Workers нет памяти и диска инстанса: нужен incremental cache и tag
  cache OpenNext (R2 — для данных и страниц, KV или D1 — для тегов и ревалидации). Без них
  `"use cache"` не переживает запрос, и каждый заход читает Firestore.
- **Картинки.** Оптимизатор Next на Workers не работает: `images.loader` — Cloudflare Images
  (свой `loader`), либо `unoptimized` для бакета.
- **`NEXT_PUBLIC_*`** встраиваются на сборке — смена `NEXT_PUBLIC_SITE_URL`,
  `NEXT_PUBLIC_VIEW_TRANSITIONS`, `NEXT_PUBLIC_FIREBASE_PROJECT_ID` требует пересборки.
- **Переменные окружения** (`KBF_DATA`, `SITE_NOINDEX` и остальные из `apphosting.yaml`) —

## Индексы Firestore

Файл `firestore.indexes.json` (формат Firebase CLI; выкатывать из репозитория `kbf` вместе с
правилами) — только то, что нужно сайту:

| Коллекция | Поля | Зачем |
| --- | --- | --- |
| `posts` | `isPublished` ASC, `publishedAt` DESC | лента новостей, sitemap, «Читайте также» |
| `posts` | `tags` CONTAINS, `isPublished` ASC, `publishedAt` DESC | лента с фильтром по тегу |

`posts` по `slug` + `isPublished` и `players` по `slug` — одиночные поля, авто-индексы.
Если индекса нет, ошибка REST в логе сервера содержит ссылку на его создание.

## Модель данных

`src/lib/types.ts` — один в один с `kbf/packages/core/lib/entities` и контрактом схемы
(задача 2, 2 ноября 2026). Даты из REST — ISO-строки.

- `memberships/{id}`: `playerId`, `playerName`, `teamId`, `teamName`, `division`, `season`,
  `number?`, `from?`, `to?`. Активная запись — `season == current && !to`. `player.teamIds`

  корректный hex, остальное отбрасывает (`normalizeHex`). Палитра админки —
  `lib/teamPalette.ts` (те же значения, что `core/lib/constants/team_palette.dart`).
- `tr?` — переводы `{ <lang>: { <field>: value } }` у `posts`, `tournaments`, `teams`,
  `coaches`, `players`, `settings/about` (см. «Языки»).

## Админка: состояние и страховки

- **`tournamentId` у матчей** — маппер админки (`games_mapper.dart`) исправлен: поле читается и

## Языки

Сейчас язык один — русский; маршрутов `[lang]` нет. Подготовлено:

- `lib/i18n.ts`: `type Locale = "ru"`, `LOCALES`, `DEFAULT_LOCALE`; `pickTr(entity, field,
  locale)` — поле из `tr.<locale>.<field>` с фолбэком на русское; `localized(entity, fields,
  locale)` — копия сущности с переводимыми полями.
- `plural`, `count` и форматирование дат (`lib/format.ts`) принимают `locale`: для `ru` —
  прежняя логика, для других — `Intl.PluralRules` / `Intl.DateTimeFormat` (время Бишкека).
  Все вызовы передают `DEFAULT_LOCALE` (параметр обязательный — tsc найдёт пропущенный).
- Модели читают `tr` как есть; списки читаются без `tr` (там переводы биографий и тел статей),
  кроме команд и турниров.

Будущая схема (не реализована):

1. **Русские адреса без префикса** остаются основными: `/news/...`, `/teams/...`.
2. **Киргизский — открытые адреса `/ky/...`** для поиска: отдельный сегмент `app/ky/...`
   (или `[lang]` с `generateStaticParams` только для не-русских языков), `hreflang`
   (`alternates.languages` в `pageMetadata`: `ru` → `/…`, `ky` → `/ky/…`, `x-default` →
   русский), `<html lang>` по языку, JSON-LD `inLanguage`.
3. **Выбор языка запоминается в cookie `lang`.** `proxy.ts` (бывший middleware) на русском
   адресе при `lang=ky` подменяет страницу (`NextResponse.rewrite` на `/ky/...`), адрес в
   строке не меняется; явный `/ky/...` всегда киргизский, cookie не нужен.
4. **Кэш и CDN**: ответ на русском адресе зависит от cookie — `Vary: Cookie` ломает кэш CDN
   (cookie у всех разные). Правильнее: rewrite только при `lang` ≠ `ru`, а такие ответы
   отдавать `Cache-Control: private` (или ключ кэша CDN по значению cookie `lang`, если
   CDN умеет — Cloudflare Cache Rules). Поисковики cookie не шлют и видят русский по
   русскому адресу и киргизский по `/ky/...` — без маскировки.
5. Данные: проекции списков дополнить путями `tr.ky.title` и т. п.; `pickTr`/`localized` с
   локалью из сегмента; строки интерфейса — словари по `Locale`.
